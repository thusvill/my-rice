# Noir Rice: Architecture and Operations

This document describes the repository as it currently exists. It is intended
as a handoff map for future maintenance, not as a claim that every planned shell
feature is already implemented.

## Project summary

Noir is a black and grayscale desktop configuration centered on the Niri Wayland
compositor. It combines Niri configuration, an AGS v3/Astal GTK4 top bar,
GTK3-based utility windows, command-line helpers, and configurations for Kitty,
Fish, Swaylock, Dunst, Wlogout, and Neovim.

The active bar is Astal/AGS. The former Waybar configuration and its popup
daemon/client remain in the repository as rollback/reference material. Normal
Niri startup no longer launches Waybar or the old popup daemon.

The project is a collection of user configuration files and scripts rather than
a compiled application. `apply.sh` copies the repository's `config/` tree into
`~/.config/` and executable helpers from `bin/` into `~/.local/bin/`.

## Repository map

| Path | Purpose |

| `config/astal/` | Active AGS v3 GTK4 shell source, popup state, theme, and settings loader. |

| `config/kitty/`, `config/fish/` | Terminal and interactive Fish defaults. |
| `config/swaylock/`, `config/dunst/`, `config/wlogout/` | Lock screen, notification daemon, and session/power menu styling. |

| `bin/noir-display-menu` | Native GTK3 display profile UI. |

The checked-out working tree has contained modifications to existing files and
untracked migration files during the Astal transition. Review `git status` before
assuming a clean baseline; generated `bin/__pycache__` bytecode is not source.
The root `nvim.log` is a local editor log, not part of the installed desktop
configuration.

## Runtime and startup

Niri starts these processes from `config/niri/config.kdl`:

1. `noir-wallpaper init` restores or selects a wallpaper and starts configured
   wallpaper cycling when enabled.
2. `noir-display-profile` waits up to 15 seconds for Niri outputs, then restores
   the saved display profile.
3. `ags run ~/.config/astal/app.tsx` starts the bar/shell process.
4. `dunst` starts notifications.

`apply.sh` also starts/restarts the AGS instance immediately when `WAYLAND_DISPLAY`
is present. It writes AGS output to
`~/.local/state/noir-rice/astal.log`. Without a Wayland session it leaves AGS for
the next Niri login. Niri configuration changes can be loaded in an active
session with:

```sh
niri msg action load-config-file
```

The shell creates one `Astal.Window` per GDK monitor. The bar uses a top-layer
window anchored across the monitor's top edge. Indicator buttons are GTK
`MenuButton`s with child `Gtk.Popover`s, so popups attach to their own buttons.
`PopupManager.ts` holds one shared active popup name; selecting a popup changes
the shared state, and selecting the active name toggles it off.

`app.tsx` loads `~/.config/noir-rice/astal.json` through `state.ts` and reads
`~/.config/astal/theme.css`. The height setting is applied in the GTK CSS; it
must not be passed as a `style` property on `Astal.Window` (that property caused
a real runtime exception and has been removed). Bar spacing and clock format
are also read from settings.

### Current AGS shell coverage

The shell source is in `config/astal/`:

- `app.tsx`: starts the AGS application, loads settings and palette CSS, and
  creates bars for connected monitors.
- `Bar.tsx`: top bar, clock, weather polling, module buttons, and popover
  attachment.
- `PopupManager.ts`: shared active popup state and toggle/close operations.
- `Popup.tsx`: popup contents and actions.
- `services.ts`: asynchronous command execution; failed commands resolve to an
  empty result so an unavailable helper does not throw through the UI.
- `state.ts`: JSON settings loader with defaults.
- `theme.css`: palette variables generated by the palette tool.

The current popup actions are a working starter surface, not the complete
reactive Astal service integration originally envisioned. Audio currently uses
`wpctl` commands and a slider; network uses `nmcli` toggle/refresh commands;
display offers brightness up/down via `noir-brightness` and opens the display
profile window; Bluetooth opens `blueman-manager`; media calls `playerctl`;
notifications call `dunstctl`; system actions call the existing lock,
screenshot, settings, and Wlogout helpers. The bar's workspace label is still a
placeholder string, and the shell does not yet render a tray, live CPU/memory/
disk/battery indicators, detailed Wi-Fi lists, device selectors, or reactive
AstalWp/AstalNetwork widgets. The dependency checker verifies AstalWp and
AstalNetwork are installed even though current popup code primarily uses CLI
helpers.

## Installation and dependency behavior

`apply.sh` installs config files and executable helpers first, then runs
`noir-astal-install` followed by `noir-astal-check`.

`noir-astal-install` considers the runtime ready when `ags`, `gjs`, `meson`,
`ninja`, `npm`, and `go` are available and GJS can import `Astal`, `AstalWp`,
and `AstalNetwork`. On Arch, if anything is missing, it:

1. Installs build dependencies with `sudo pacman`: `base-devel`, `git`, `npm`,
   `meson`, `ninja`, `go`, `gobject-introspection`, GTK3/GTK4, and both
   layer-shell development libraries.
2. Uses `yay` or `paru`; if neither exists, it clones the official `yay` AUR
   repository into a temporary directory and builds/installs it with `makepkg`.
3. Installs `aylurs-gtk-shell-git` and `libastal-meta` through the AUR helper.
4. Rechecks the required commands and GI imports.

The Arch installation can prompt for sudo credentials and AUR build/package
confirmation. On non-Arch distributions the installer reports the missing
components and exits with instructions; it does not currently automate other
package managers.

`noir-astal-check` checks command availability and the three GI imports, then
runs `ags bundle` against the deployed `~/.config/astal/app.tsx`, bounded by a
60-second timeout. It intentionally avoids `ags types`: that command invokes
`npx` to fetch a generator and was the cause of `apply.sh` appearing to freeze.

## Apply, backups, and update behavior

`apply.sh` determines the repository directory relative to the script and
creates a timestamped backup at:

```text
~/.local/state/noir-rice/backups/YYYYMMDD-HHMMSS/
```

Before copying each file, it copies an existing destination into the matching
relative backup path. It then copies all regular files under `config/` into
`~/.config/` and most files at the top of `bin/` into `~/.local/bin/`, making
those helpers executable. The rollback-only `noir-topbar` and `noir-popup`
helpers are deliberately skipped by installation. Existing copies of those
helpers are not removed automatically.

Tracked JSON defaults under `config/noir-rice/` are copied on each apply and
can therefore replace deployed JSON values; the pre-copy backup is the recovery
point. Some other runtime state, such as display profile and palette state, is
created by tools and is not necessarily present in the repository.

`noir-backup` creates a separate timestamped manual backup covering Niri,
Astal, Waybar, Kitty, Swaylock, Noir state, and Neovim configurations.

## Settings and persistence

The main settings application is a Python/GTK3 program. It has searchable
pages for Wallpaper, Appearance, Launcher, Astal Shell, Terminal, Editor,
Displays, Lock Screen, Window Manager, Presets & Dotfiles, and Diagnostics.
Most settings pages write their configuration directly and some live-preview
changes with debounced callbacks. The Astal page currently exposes bar height,
spacing, clock format, and weather location, plus reload and dependency-check
buttons. Saved Astal preferences live in:

```text
~/.config/noir-rice/astal.json
```

Other state/config files include:

| File | Stored information |
| --- | --- |
| `noir-rice/astal.json` | Bar height/spacing, clock format, weather location, opacity, and visible module names. |
| `noir-rice/display.json` | Selected display profile (`primary`, `secondary`, `mirror`, or `extend`). |
| `noir-rice/lockscreen.json` | Wallpaper, blur, clock visibility/format/size, and extended clock appearance/position fields. |
| `noir-rice/wallpaper.json` | Wallpaper automation and dithering preferences, including startup randomization, cycling, interval, dithering method/colors/pattern. |
| `noir-rice/palette.json` | Palette enabled flag, mode (`accent`, `background`, `full`), style/contrast controls, source, and extracted colors. |
| `noir-rice/launcher.json` | Launcher visibility/options, prompt/dimensions/results, currency, and rates. |
| `noir-rice/nvim.json` | Theme colors and editor options consumed by `colors/noir.lua`. |
| `kitty/kitty.conf` | Kitty colors and terminal preferences. |
| `swaylock/config` | Swaylock's base colors and indicator appearance. |
| `niri/config.kdl` | Compositor settings; Niri itself persists no Noir-specific runtime state here beyond the text config. |

The UI has old Waybar editing methods still present in `noir-settings` for
legacy compatibility. The visible navigation now exposes an Astal page, but
those old methods still reference `~/.config/waybar` and should not be treated
as the active shell settings implementation. The preset/reload paths also
retain some Waybar-oriented calls and merit cleanup before relying on the
preset feature for Astal.

## Helpers and subsystem behavior

### Wallpaper and palette

`noir-wallpaper` looks in `~/Pictures/Wallpapers` for JPG/JPEG/PNG/WebP files.
It supports startup restoration, random selection, Fuzzel selection, favorites,
slideshow/cycle controls, and optional ImageMagick dithering. `swaybg` displays
the selected image. It caches the displayed path, original source, PID files,
favorites, and dithered copy under `${XDG_CACHE_HOME:-~/.cache}/noir-rice/`.
Wallpaper automation preferences are in `noir-rice/wallpaper.json`.

`noir-palette` samples the active wallpaper, derives readable background,
surface, accent, foreground, muted, border, and dominant colors, and persists
them in `palette.json`. It writes CSS variables to `astal/theme.css`, updates
Kitty, Neovim state, and Dunst as applicable, then reloads AGS, Dunst, and
Kitty when those commands are available. `accent` mode restores base surfaces
before applying accent colors; `background` and `full` can change surfaces.
The legacy Waybar palette function remains in the script but is no longer used
by the active apply flow.

### Display controls

`noir-display-menu` is a GTK3 window that reads Niri's JSON output state, shows
connected outputs, polls for changes once per second, and provides Primary
only, Secondary only, Mirror, and Extend actions. It saves its selection to
`noir-rice/display.json`. Mirror mode requires `wl-mirror`; Extend arranges
outputs left to right using their logical widths. `nwg-displays` is available
as an optional fine-tuning tool.

`noir-display-profile` is a startup helper. It identifies an internal display
by an `eDP`, `LVDS`, or `DSI` name prefix, falls back to the first output, and
applies the saved profile after Niri output discovery. With no external output,
it forces Primary only.

### Launcher and settings

`noir-launcher` is a GTK3 Super+D overlay with desktop application search,
calculator parsing, and currency conversion/rate refresh. Its behavior is
stored in `launcher.json`. The main settings GUI is `noir-settings`; it provides
wallpaper previews/dithering and automation, palette controls, launcher
controls, Kitty and Neovim customization, Swaylock settings, Niri layout
controls, diagnostics, and backup actions. Display profile selection is
handled by the separate display menu.

### Locking, notifications, screenshots, and session

`noir-lockscreen` creates a blurred wallpaper background with an optional clock
using ImageMagick and fontconfig, then executes Swaylock. If the image cannot
be created it falls back to the configured Swaylock color screen. Preview mode
is available with `--preview`.

`noir-screenshot` opens a GTK3 chooser for the whole screen, selected area, or
focused Niri window. Capture uses `grim`; area selection uses `slurp`; if
available, the PNG is copied to the clipboard with `wl-copy`. `Print Screen`
opens this chooser, while `Super+Shift+S` runs a direct area/fullscreen capture
command.

`noir-notifications` prints the Dunst history count for legacy/custom indicator
use. The Astal notification popup calls `dunstctl` actions directly. Wlogout
provides logout, reboot, shutdown, and firmware restart choices.

### Brightness, audio, network, and media

`noir-brightness` prints an internal brightness indicator using
`brightnessctl`; with `up` or `down`, it adjusts internal brightness and any
detected DDC/CI displays by five percentage points. External brightness
requires `ddcutil` and suitable permissions.

The Niri media keys use `wpctl`, `brightnessctl`, and `playerctl`. Astal popup
actions similarly use `wpctl`, `nmcli`, `playerctl`, `dunstctl`, and external
helpers. Some operations may need the relevant system service, hardware, or
permissions. Bluetooth's current popup action opens `blueman-manager` instead
of providing an in-popup device list.

## Niri controls

The current config uses US keyboard layout, flat mouse acceleration, focus
follows mouse, 8-pixel gaps, centered-column mode `never`, and a 50% default
column width. Focus ring colors are grayscale. It disables client-side
decorations and the startup hotkey overlay.

Important keybindings:

| Keys | Action |
| --- | --- |
| `Super+T`, `Super+D`, `Super+S`, `Super+P` | Kitty, launcher, settings, display menu. |
| `Super+Escape`, `Super+L`/`Super+Ctrl+L` | Wlogout, Swaylock. |
| `Super+W`, `Super+E` | Brave, file manager. |
| `Super+Shift+W`, `Super+Ctrl+W` | Wallpaper picker, random wallpaper. |
| `Super+1` through `Super+9` | Focus workspace. Up/Down and brackets cycle workspace; Shift+brackets move columns. |
| `Super+Left/Right` or H/J/K/L | Focus columns/windows. Shift variants move columns/windows. |
| `Super+Q`, `Super+F`, `Super+R` | Close, fullscreen, cycle column width. |
| `Print`, `Super+Shift+S` | Screenshot chooser, direct area/fullscreen screenshot. |
| XF86 audio/brightness/media keys | Adjust default PipeWire devices, brightness, and player controls. |

Launcher and screenshot windows have Niri floating/focus rules. There is no
current Waybar-specific layer rule.

## Dependencies

Core desktop commands listed by the README include Niri, AGS, GJS, Kitty, Fish,
Fuzzel, Swaybg, Swaylock, Wlogout, Dunst, YAD, jq, grim, brightnessctl, and
playerctl. AGS v3 needs Astal GTK4 runtime libraries. The current installer
also checks AstalWp/AstalNetwork and build tooling.

Optional integrations include `curl` for wttr.in weather, `nmcli`/NetworkManager
for network controls, `wpctl`/PipeWire for audio, `blueman-manager`/BlueZ for
Bluetooth, `ddcutil` for external monitor brightness, `wl-mirror` for display
mirroring, `nwg-displays` for detailed display configuration, ImageMagick for
wallpaper dithering and lockscreen image composition, `slurp` for region
screenshots, `wl-copy` for screenshot clipboard, `fc-match` for lockscreen
fonts, and `notify-send` for notifications.

## Validation and troubleshooting

Useful checks:

```sh
noir-astal-check
ags bundle ~/.config/astal/app.tsx /tmp/noir-astal.js --root ~/.config/astal --gtk 4
niri validate -c ~/.config/niri/config.kdl
```

AGS startup output is stored by `apply.sh` at
`~/.local/state/noir-rice/astal.log`. A successful `ags bundle` only proves the
entrypoint compiles; it does not prove a Niri session is running or that a
window is visible. To inspect the live AGS instance, use `ags list`; to restart
the default instance from a Wayland terminal, use:

```sh
ags quit --instance ags
ags run ~/.config/astal/app.tsx
```

Known issues and boundaries:

- GTK theme-parser and Adwaita dark-preference warnings have been observed;
  they were non-fatal. A previous fatal `<scale>` JSX intrinsic was replaced
  with AGS's `<slider>`, and a previous invalid `style` prop on `Astal.Window`
  was moved into CSS.
- The deployed Neovim init was once observed asking for colorscheme `nori`,
  while this repository defines/selects `noir`. The valid colorscheme name is
  `noir` (`config/nvim/colors/noir.lua`).
- README descriptions are broader than the current Astal implementation in
  some areas. Check `config/astal/Popup.tsx` before assuming a control is
  reactive or fully implemented.
- Waybar-specific methods and configuration remain in the repo, but normal
  startup uses AGS. Avoid changing Waybar files as a way to configure the
  active shell.
- `apply.sh` copies all configuration files, backs up destinations, may install
  system/AUR packages on Arch when dependencies are missing, and restarts AGS
  inside an active Wayland session. It does not automatically reload every
  other already-running desktop application.

## Design intent and incomplete work

The migration direction is one long-lived AGS v3/GTK4 process owning the bar
and native anchored popovers. The intended next stages are reactive Astal
bindings for audio/network/Bluetooth/media/notifications/tray, complete module
visibility and appearance settings, improved live state presentation, and
removal or isolation of dormant Waybar editor code. Keep optional services
failure-tolerant and avoid reintroducing pointer-coordinate popup placement.
